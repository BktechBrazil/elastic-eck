ILM & Hot-Warm

Automatizar o ciclo de vida dos índices — e desenhar tiers de temperatura com nodeSets no ECK.

O problema

Logs e métricas são muito lidos quando novos e quase nunca quando velhos — mas ocupam disco caro.

Sem automação, alguém cria, move, otimiza e apaga índices na mão. O ILM faz isso por política.

As fases do ciclo

Hot

escrita + leitura
rollover

Warm

só leitura
forcemerge, allocate

Cold

rara
allocate, snapshot

Delete

fim
delete
Ex.: rollover a 50 GB/7d → warm em 30d (forcemerge) → delete em 90d.

Rollover + Data Streams

Não escrever para sempre no mesmo índice: ao atingir um limite, cria-se o próximo.

  • Data stream = um nome de escrita (logs-app)…
  • …sobre índices de apoio girados: .ds-...-000001, -000002
  • Você escreve/consulta o nome único; o ILM cuida do resto
Um index template amarra padrão de nome + data stream + política + mapping.

O ângulo ECK: tiers = nodeSets

nodeSets:
  - name: hot
    config: { node.roles: ["data_hot", "ingest"] }   # SSD
  - name: warm
    config: { node.roles: ["data_warm"] }             # disco barato
A ação allocate (warm) move os shards para os pods warm. Topologia por temperatura = desenhar nodeSets.
