Preparação de Ambiente

Nivelar o terreno: kernel, rede e runtime de containers antes de instalar o Kubernetes.

Por que preparar o host?

Kubernetes e Elasticsearch fazem exigências específicas ao sistema operacional. Pular esta etapa gera erros confusos lá na frente:

  • kubelet não sobe → swap ligado
  • pod do Elasticsearch em crash loop → vm.max_map_count baixo
  • pods sem comunicação → módulos de rede ausentes
Terreno nivelado agora = 90% menos dor de cabeça depois.

O detalhe do vm.max_map_count

O Elasticsearch usa memory-mapped files para ler índices com eficiência. Cada segmento consome "áreas de mapeamento de memória".

  • Padrão do Linux: 65530 — baixíssimo.
  • ES 8.16+ / 9.x exige: 1048576.
Vantagem da VM única: setamos no host e todos os pods do ES herdam — sem initContainers privilegiados (que seriam obrigatórios em cluster gerenciado).

Aplicando os parâmetros

# swap
sudo swapoff -a

# sysctl: rede + Elasticsearch
sudo tee /etc/sysctl.d/99-eck.conf <<EOF
net.ipv4.ip_forward = 1
net.bridge.bridge-nf-call-iptables = 1
vm.max_map_count = 1048576
EOF
sudo sysctl --system

Runtime: containerd

O Kubernetes não roda containers sozinho — delega a um runtime. Usamos o containerd (o mesmo que o Docker usa por baixo).

sudo apt-get install -y containerd
containerd config default | sudo tee /etc/containerd/config.toml
# alinhar ao systemd (cgroups):
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml
sudo systemctl restart containerd
Atenção: esquecer o SystemdCgroup = true deixa o kubelet instável.

Checklist final ✅

  • free -h → Swap = 0B
  • sysctl vm.max_map_count → 1048576
  • lsmod | grep br_netfilter → carregado
  • systemctl is-active containerd → active
