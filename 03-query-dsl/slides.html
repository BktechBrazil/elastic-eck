Explorando dados: Query DSL

Buscar, filtrar e agregar em JSON — a linguagem que faz o Elastic ser um motor de busca e de análise.

Como o Elastic "pensa"

  • Documento = um JSON · Índice = coleção de documentos
  • Buscar = GET /indice/_search com um corpo JSON
  • Resposta: hits.total, hits.hits, aggregations
  • _score = quão bem cada documento casa (relevância)

As duas famílias de consulta

FamíliaPerguntaAfeta _score?
Full-text"Quão relevante é o texto?"Sim
Term-level"É exatamente igual?"Não (filtro)
Full-text em campos text · Term-level em keyword, números, datas. Ex.: category vs category.keyword.

match vs term

# full-text: relevância
GET ecommerce/_search
{ "query": { "match": { "category": "Men's Clothing" } } }

# term-level: valor exato (keyword)
GET ecommerce/_search
{ "query": { "term": { "customer_gender": "MALE" } } }
Pegadinha: term em campo text quase nunca casa — use .keyword.

Compor com bool

CláusulaSignificadoPontua?
mustPrecisa casarSim
shouldOpcional (bônus)Sim
filterPrecisa casarNão · cacheável
must_notNão pode casar—
Performance: critérios sim/não (data, status, categoria) vão em filter.

bool na prática

{
  "query": { "bool": {
    "must":     [ { "match": { "category": "Women's Shoes" } } ],
    "filter":   [ { "range": { "taxful_total_price": { "gte": 40 } } } ],
    "must_not": [ { "term":  { "customer_gender": "MALE" } } ]
  } }
}

Agregações: de busca a análise

  • Bucket — agrupam (terms, date_histogram)
  • Metric — calculam (avg, sum, max, cardinality)
{ "size": 0, "aggs": {
  "por_categoria": {
    "terms": { "field": "category.keyword" },
    "aggs": { "receita": { "sum": { "field": "taxful_total_price" } } }
  }
}}
Bucket que contém metric = a estrutura de quase todo painel do Kibana.
