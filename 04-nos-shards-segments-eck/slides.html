Módulo 04

Nós, Shards e Segments

A arquitetura interna do Elasticsearch e sua tradução direta para nodeSets, pods e PVCs no ECK.

Do documento ao disco

Índice — coleção lógica ("pedidos")
└─ Shard — fatia do índice = um índice Lucene completo
   └─ Segment — arquivos imutáveis, fundidos ao longo do tempo
Segments imutáveis → deletar só marca; espaço volta no merge.

Primary × Réplica

  • Primary — onde o documento é escrito; nº fixo na criação
  • Réplica — cópia em outro nó: HA + throughput de leitura
Regra: réplica nunca no mesmo nó do primary → em single-node a réplica fica unassigned e o cluster fica yellow. Nos labs: number_of_replicas: 0.

Papéis de nó (node.roles)

PapelFunção
masterCoordena o cluster (estado, alocação)
data_hot/warm/coldGuardam shards (base do hot-warm)
ingestExecutam ingest pipelines
mlJobs de Machine Learning
coordinatingSem papel: roteiam e juntam resultados

A tradução para o ECK

ElasticsearchECK
Um nóUm Pod (StatefulSet)
Grupo de nós c/ mesmo papelUm nodeSet
Escalar nº de nósMudar count
Disco de um nóUm PVC
Topologia hot-warmVários nodeSets
Arquitetura de cluster no ECK = desenhar a lista de nodeSets.

Topologia = lista de nodeSets

nodeSets:
  - name: masters
    count: 3
    config: { node.roles: ["master"] }
  - name: data
    count: 6
    config: { node.roles: ["data", "ingest"] }
O operator cuida de identidade, discos e rolling changes.

As APIs _cat que você vai amar

GET _cat/nodes?v
GET _cat/shards/loja?v          # prirep: p/r · state: STARTED/UNASSIGNED
GET _cat/segments/loja?v        # quantos segments, docs deletados
POST loja/_forcemerge?max_num_segments=1
force merge é caro em I/O: só em índices que não recebem mais escrita.

Resultado ✅

  • índice → shard → segment
  • primary × réplica e o "yellow" em single-node
  • nó = pod · grupo = nodeSet · escala = count
  • _cat e force merge
