Módulo 01

Instalação do Kubernetes + ECK

Do zero a um cluster single-node com kubeadm, o operator ECK e o primeiro Elasticsearch rodando.

A grande ideia do Kubernetes

Você declara o estado desejado ("3 réplicas, 4 GB cada, este disco") e o Kubernetes trabalha para manter a realidade igual à declaração.

Paramos de instalar software passo a passo e passamos a declarar intenções em YAML.

Anatomia de um cluster

Control plane (cérebro)

  • api-server — porta de entrada do kubectl
  • etcd — banco do estado do cluster
  • scheduler — escolhe o nó de cada pod
  • controllers — corrigem desvios

Nó de trabalho

  • kubelet — agente do nó
  • containerd — roda os containers
  • CNI — rede dos pods
No lab, um nó só acumula os dois papéis (removemos o taint do control plane).

Objetos que usaremos sempre

📦

Pod

Menor unidade: um ou mais containers juntos.

🗂️

Namespace

Compartimento lógico (elastic-system, elastic).

💾

PVC

Pedido de disco durável — dados do ES.

🏭

StorageClass

Receita que provisiona discos sob demanda.

🔐

Secret

Senhas e certificados gerados pelo operator.

Por que um operator?

Instalar Elasticsearch é fácil; operá-lo é difícil: formar cluster, TLS, senhas, rolling upgrade sem perder dados, escalar com segurança.

O operator ECK empacota esse conhecimento e roda dentro do Kubernetes, estendendo-o com CRDs: Elasticsearch, Kibana, Agent, Beat.

O operator em ação

você kubectl apply ▶ recurso Elasticsearch (CRD) ▶ operator observa
↳ cria StatefulSetServiceSecret TLSSecret senhaPVC
Um YAML de 10 linhas → um cluster Elasticsearch inteiro, seguro e monitorado.

Ferramentas: kubectl & helm

kubectl

Canivete suíço: apply, get, describe, logs, port-forward, ler Secrets.

helm

Gerenciador de pacotes. Instala o chart oficial eck-operator em um comando.

A. Subir o cluster

# binários + init do control plane
sudo apt-get install -y kubelet kubeadm kubectl
sudo kubeadm init --pod-network-cidr=192.168.0.0/16

# kubeconfig
mkdir -p ~/.kube && sudo cp /etc/kubernetes/admin.conf ~/.kube/config

# rede (Calico) + liberar o nó
kubectl create -f .../calico/tigera-operator.yaml
kubectl taint nodes --all node-role.kubernetes.io/control-plane-

B. Storage + Helm

# StorageClass dinâmica como default
kubectl apply -f .../local-path-storage.yaml
kubectl patch storageclass local-path -p \
  '{"metadata":{"annotations":{"storageclass.kubernetes.io/is-default-class":"true"}}}'

# metrics-server (kubectl top) e helm
kubectl apply -f .../metrics-server/components.yaml
curl -fsSL .../get-helm-3 | bash

C. Instalar o operator ECK

helm repo add elastic https://helm.elastic.co
helm repo update
helm install elastic-operator elastic/eck-operator \
  -n elastic-system --create-namespace --version 3.4.1
# validação
kubectl -n elastic-system get pods      # operator Running
kubectl get crd | grep k8s.elastic.co

D. Validar: ES + Kibana

kubectl apply -n elastic -f manifests/elasticsearch-quickstart.yaml
kubectl apply -n elastic -f manifests/kibana-quickstart.yaml

# senha do usuário elastic
kubectl -n elastic get secret quickstart-es-elastic-user \
  -o go-template='{{.data.elastic | base64decode}}'

# acessar o Kibana
kubectl -n elastic port-forward service/quickstart-kb-http 5601
Abra https://localhost:5601 — usuário elastic.

Resultado ✅

  • kubectl get nodes → um nó Ready
  • operator ECK Running e CRDs registradas
  • Elasticsearch green/yellow + Kibana acessível
