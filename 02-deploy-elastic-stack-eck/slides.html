Módulo 02

Deploy do Elastic Stack no ECK

O que o operator cria a partir de 10 linhas de YAML — e como configurar um cluster de forma consciente.

A mudança de paradigma

Antes: baixar pacote, editar elasticsearch.yml, abrir portas, TLS na mão, criar usuários — por nó.

Agora: um YAML declarativo, e o operator executa e mantém.

Você descreve o desejo; o operator materializa e reconcilia o resto.

Anatomia: nodeSets

Um nodeSet é um grupo de nós com a mesma configuração:

  • count — quantos nós
  • config — vai para o elasticsearch.yml (papéis, mmap...)
  • podTemplate — CPU/memória, heap (ES_JAVA_OPTS), afinidade
  • volumeClaimTemplates — o disco PVC de cada nó
Cluster com papéis separados (master/data) = apenas vários nodeSets na lista (Módulo 04).

Segurança "de graça" 🔐

O ECK liga segurança por padrão: TLS em HTTP e transport, CA interna que gera e rotaciona certificados, senha do elastic em Secret.

# senha
kubectl -n elastic get secret lab-es-es-elastic-user \
  -o go-template='{{.data.elastic | base64decode}}'
# CA para validar TLS sem -k
kubectl -n elastic get secret lab-es-es-http-certs-public \
  -o go-template='{{index .data "ca.crt" | base64decode}}' > ca.crt

Formas de acesso

  • port-forward — túnel do terminal ao Service (lab)
  • NodePort / LoadBalancer — expõe fora do cluster
  • Ingress — roteador HTTP(S) com hostname (produção)
kubectl -n elastic port-forward service/lab-kb-http 5601

No laboratório

  • Dissecar o quickstart e provar a reconciliação (apagar um pod)
  • Recriar como lab-es com 0 réplicas → cluster green
  • Subir o Kibana lab-kb ligado a ele
  • Carregar os Sample data (eCommerce, web logs)
Esses dados alimentam os Módulos 03, 05 e 07.

Resultado ✅

  • lab-es e lab-kb em green
  • Você sabe recuperar senha e CA
