Ingestão no Kubernetes

Beats, Logstash e Elastic Agent — todos gerenciados pelo mesmo operator ECK, via CRDs.

"Tem operator?" — Sim!

O mesmo operator ECK gerencia a ingestão. Não é preciso outro operator.

A mágica do elasticsearchRef

Ao declarar elasticsearchRef / kibanaRef, o operator injeta host, usuário, senha e CA de TLS automaticamente.

Você nunca cola credenciais ou certificados no manifesto do coletor.

Quem é quem

🪶

Beats

Leves e especializados: Filebeat (logs), Metricbeat (métricas). Clássicos.

🤖

Elastic Agent

Um agente unifica os Beats + integrations; gerenciável por Fleet. Recomendado hoje.

🛠️

Logstash

Motor de pipeline: parse (grok), enriquecimento, roteamento, buffering.

O padrão de fluxo

Beats / Agent▶ Logstash (opcional)▶ Elasticsearch
Coletores de ponta pegam os dados; o Logstash entra no meio só quando há transformação/roteamento.

Como rodam no Kubernetes

  • DaemonSet — um pod por nó (coleta de logs/métricas do host) → Beats e Agent
  • Deployment — pipeline central / Fleet Server → Logstash, Fleet
  • Privilégios — ServiceAccount + RBAC, runAsUser: 0, hostPath de /var/log
Os manifests do módulo já trazem o RBAC pronto.
